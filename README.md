# ChatGPT 任务完成提醒

Chrome Manifest V3 扩展。监控当前仍然打开的 ChatGPT 页面，在任务完成、等待确认或失败时发送 Windows 通知，并提供当前会话内的消息队列。

## v0.6.8 核心变化

- 发送后只有在页面确实新增用户消息时才创建任务；未登录、发送失败或跳转登录页不会留下无效任务记录。
- 点击“加入队列”后立即继续输入时，若异步入队尚未完成会安全中止本次入队并保留新草稿。
- 非活动标签页不再依赖可能暂停的 `requestAnimationFrame`；每个标签页都可独立入队、更新面板并等待会话执行权。
- 提供 `scripts/update-installed-extension.ps1`，可备份并覆盖固定的解压扩展目录，避免仓库、下载目录和 Chrome 实际加载版本不一致。
- 保留 v0.6.7 的项目会话活动输入框适配，项目页和普通会话统一选择当前可见、可用的输入框。

## v0.6.7 核心变化

- 修复从 ChatGPT 项目主页新建聊天后，SPA 跳转保留隐藏旧输入框，导致正式会话中的新内容无法加入队列的问题。
- 新增活动输入框适配器，优先选择当前聚焦、可见且可用的输入框；若页面短时间挂载多个输入框，则选择最新的可见实例。
- 任务监控和消息队列继续复用原有输入框逻辑，但所有 `querySelector` 读取都会先经过统一适配，避免两个模块再次出现不同判断。
- 增加真实项目主页、项目正式会话 URL、隐藏旧输入框和重复输入框挂载的回归测试。

## v0.6.6 核心变化

- 队列仍按“标签页 + 会话”独立保存，执行权仍按 ChatGPT 会话唯一互斥。
- 每次文档加载都会生成新的页面实例 ID，刷新、完整导航和 BFCache 恢复不再只依赖可复用的 `tabId`。
- 会话执行租约现在按“标签页 + 页面实例”校验；旧页面实例不能刷新、释放或重新抢回新页面实例的租约。
- 同一标签刷新后可立即接管旧页面实例留下的租约，不需要等待 120 秒租约超时。
- 同一会话打开多个标签页时，仍只有一个标签自动发送；其他标签保留各自队列并等待执行权。

## v0.6.5 核心变化

- 每个 Chrome 标签页维护自己的消息队列；即使打开同一个 ChatGPT 会话，队列内容也不再合并。
- 同一 ChatGPT 会话使用独立的会话级执行租约，同一时刻只允许一个标签页自动发送和继续消费队列。
- 获得执行权的标签会连续执行自己的队列；其他同会话标签保留各自队列并显示等待状态，执行权释放后再继续。
- 标签页关闭时清理该标签的队列与执行租约；刷新时保留队列，但中断中的任务仍安全暂停。

- 新回复的“复制回复”按钮作为高可信完成信号；按钮不可用时仍使用正文稳定 4 秒的兜底判断。
- 项目路径包装变化只要会话 ID 相同就继续监控。
- Chrome Tab 切换或休眠恢复产生的短暂路由会等待确认，不会立即停止旧任务。

- 兼容新版 ChatGPT 的 `#composer-submit-button`，并等待发送按钮完成渲染和启用。
- 发送失败会显示准确原因；页面结构类故障会暂停队列并恢复原草稿，不再自动循环重试。
- 5 秒内相同内容不会被快速重复加入队列。
- 队列状态、暂停状态和覆盖确认优先显示，不再被“不能加入新消息”的提示覆盖。

- 修复新建聊天从首页或项目草稿页自动跳转到 `/c/<会话ID>` 时被误判为切换会话、导致首条任务监控丢失的问题。
- 增加限时 URL 提升机制，只允许活动任务从草稿页安全绑定到首次生成的正式会话 URL。
- 修复同一标签完整导航到另一个 ChatGPT 会话时，旧任务仅凭 `tabId` 被错误恢复到新页面的问题。
- 修复队列发送确认尚未完成时，手动状态纠偏可能过早解除活动项的问题。
- 自动执行的草稿覆盖确认继续使用自动派发的稳定性与运行状态保护，不再降级为手动派发。

- 取消后台标签、折叠标签组、看门狗和自动恢复机制。
- 只监控当前仍然打开的 ChatGPT 页面；切换标签页不受影响，关闭页面后立即停止监控。
- 不会因为任务未完成而创建、刷新或重新打开任何 ChatGPT 标签。
- “立即执行”以页面实时 DOM 状态为准，会主动纠正已经结束但缓存仍显示运行中的状态。
- 修复编辑队列消息时浏览器卡死：大文本改为原子写入，写入期间忽略输入框 MutationObserver。
- 队列列表只渲染 240 字预览，不再反复把完整长文本插入 DOM。
- 队列元数据与完整消息正文拆分存储，大文本入队不再重写所有历史正文。
- 加入队列、编辑和立即执行时先显示操作反馈，并增加防重复点击锁。
- 任务发送改为确认成功后建档，消息通道失败会有限重试。
- 修复刷新恢复、同标签切换会话、跨标签队列写入竞争和旧队列重复迁移。

## 工作方式

1. 用户在 ChatGPT 当前页面发送消息后，扩展开始监控该页面。
2. 可以切换到其他浏览器标签页，原 ChatGPT 页面仍会继续运行和通知。
3. 新建聊天被 ChatGPT 自动分配正式会话 URL 时，当前任务会安全迁移到该 URL。
4. 关闭该 ChatGPT 页面后，扩展将任务标记为已停止，不再继续检测。
5. 扩展不会自动创建后台标签，也不会自动重新打开已关闭页面。
6. 页面刷新时可恢复同一标签中的任务状态；中断的队列任务会暂停，避免重复发送。

## 消息队列

- ChatGPT 正在回答时，可以继续在输入框中输入下一条消息并点击 **加入队列**。
- 当前回答完成且页面稳定后，自动执行下一条。
- 输入框已有草稿时，自动执行会先询问是否覆盖。
- **编辑**：把队列内容取回输入框，原输入存在内容时先确认。
- **立即执行**：实时检查页面是否仍在生成，页面已空闲时立即发送。
- 支持删除、上移、下移、暂停、继续和失败重试。
- 队列按“标签页 + 会话”隔离；同一会话的多个标签页不会共享队列，但会竞争唯一自动执行权。
- 执行权按标签页和当前页面实例共同识别，旧页面实例无法干扰刷新后的新页面。
- 项目主页进入正式会话后，扩展会忽略遗留的隐藏输入框并绑定当前可见输入框。
- 单条队列消息最多保存 200,000 个字符；界面只显示短预览。

## 通知格式

```text
标题：用户问题或队列消息的第一行/首句
正文：思考了 37m 51s，回复正文第一行
```

## 安装

1. 从 GitHub Releases 下载最新 `chatgpt-task-notifier-vX.Y.Z.zip`。
2. 解压 ZIP。
3. Chrome 打开 `chrome://extensions/`。
4. 开启右上角“开发者模式”。
5. 点击“加载已解压的扩展程序”，选择解压后的文件夹。
6. 打开扩展面板，点击“测试 Windows 通知”。

## 已知边界

- 扩展依赖 ChatGPT 网页 DOM；网页结构变化后可能需要更新识别规则。
- 队列只支持纯文本，不包含附件、图片、模式选择或工具配置。
- 页面刷新时正在执行的队列任务会暂停，需要用户确认后继续，避免重复发送。

## 隐私

扩展不调用 ChatGPT 私有接口，不读取登录 Cookie，也不向第三方服务器上传聊天内容。任务状态和消息队列只保存在本机 `chrome.storage.local`。完整说明见 `PRIVACY.md`。

## 项目结构

- `background.js`：当前页面任务状态、会话 URL 绑定、通知和面板消息路由。
- `content.js`：ChatGPT 页面任务状态识别和草稿页到正式会话的安全迁移。
- `queue-lease-guard.js`：为每个页面文档生成独立身份，并保护会话级执行租约不被旧页面实例误刷新或误释放。
- `chatgpt-dom.js`：统一选择当前聚焦、可见且可用的 ChatGPT 输入框，过滤项目跳转残留的隐藏旧输入框。
- `queue-core.js`：消息队列数据结构和纯函数。
- `queue-v060.js`：队列 UI、拆分存储、实时状态纠偏和自动发送。
- `popup.*`：扩展设置和最近任务。
- `tests/`：静态架构、任务生命周期、项目路由、输入框选择、旧数据兼容、租约竞争和队列纯函数测试。
