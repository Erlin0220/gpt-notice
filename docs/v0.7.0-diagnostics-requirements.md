# gpt-notice v0.7.0 需求文档：本地诊断中心与统一页面状态适配

> 设计日期：2026-07-29
> 基线版本：v0.6.12
> 目标版本：v0.7.0

## 1. 背景

v0.6.x 已完成当前页面任务监控、Windows 通知、按标签页隔离的消息队列、同会话执行租约、刷新安全暂停、项目会话输入框适配和基础 Playwright 回归。

当前主要风险已经从“核心流程缺失”转为“ChatGPT DOM 变化后的兼容性判断和故障定位困难”：

1. 任务监控器和消息队列分别维护停止按钮、等待确认、忙碌状态、错误提示、消息节点和回复复制按钮等判断，规则可能逐渐不一致。
2. 当前页面适配层只统一了输入框选择，没有统一完整的页面状态快照。
3. Popup 只能显示设置和任务列表，不能说明当前页面为什么无法加入队列、为什么暂停、哪个兼容信号缺失。
4. 异常信息主要存在于浏览器控制台，用户无法快速复制一份不含聊天正文的诊断报告。
5. ChatGPT 页面结构变化时，现有逻辑可能表现为“没有按钮”“状态一直执行中”“队列不继续”，但缺少统一的健康状态和安全降级规则。

## 2. 目标

v0.7.0 建立一个由任务监控器和消息队列共同使用的页面状态适配层，并在扩展 Popup 中提供完全本地、默认脱敏的诊断中心。

用户应能够：

- 查看扩展、通知权限、当前 ChatGPT 页面和队列的健康状态。
- 明确知道自动执行被阻止或队列被暂停的原因。
- 一键复制诊断摘要或下载 JSON 诊断文件。
- 在不泄露完整问题、回复、队列正文和登录信息的前提下，把诊断结果用于排查问题。
- 在 ChatGPT DOM 信号不可靠时得到安全暂停，而不是发生重复发送或错误覆盖。

## 3. 非目标

v0.7.0 不包含：

- 关闭 ChatGPT 标签页后继续监控。
- 创建后台标签、隐藏窗口、折叠标签组或自动恢复已关闭页面。
- 调用 ChatGPT 私有 API、读取 Cookie 或上传诊断信息到服务器。
- 自动修复 ChatGPT 页面、自动刷新页面或绕过真人验证。
- 在诊断报告中包含完整问题、回复、队列正文、Cookie、访问令牌或页面 HTML。
- 附件、图片、模型、工具和模式配置队列。
- Chrome Web Store 正式发布。

## 4. 核心概念

### 4.1 页面状态快照

页面状态快照是同一时刻对 ChatGPT 页面可观测状态的只读结果，由统一适配层生成，任务监控器和消息队列不得再各自实现同类 DOM 判断。

快照至少包含：

- 页面是否已完成加载。
- 当前活动输入框是否存在、可见、可用及其文本长度。
- 发送、停止、等待确认等控制是否存在且可用。
- 用户消息数、助手消息数、最新助手回复哈希、复制回复按钮数量。
- 页面是否显示忙碌状态或明确错误。
- 当前路由类别：主页、项目主页、临时会话、正式会话或非 ChatGPT 页面。
- 兼容性健康状态和原因。

快照不得包含完整输入框文本、完整消息正文或原始页面 HTML。

### 4.2 兼容性健康状态

统一使用三种状态：

- `healthy`：核心信号存在且没有互相冲突，任务监控和队列可以正常工作。
- `degraded`：部分非关键或可替代信号缺失，但仍可依靠安全兜底继续监控；界面需提示具体原因。
- `blocked`：核心信号缺失、互相冲突或无法安全判断，自动队列必须暂停，不得尝试发送。

健康状态只描述页面适配能力，不等同于任务状态或队列状态。

### 4.3 诊断事件

诊断事件记录重要状态转换，不记录聊天正文。事件至少覆盖：

- 页面兼容性状态变化。
- 任务开始、完成、等待操作、失败和停止。
- 队列加入、派发、确认、完成、失败和暂停。
- 会话执行租约获取、等待、续期和释放。
- 消息发送尝试及失败原因。
- Service Worker 消息通信失败。

事件采用固定上限的环形记录，默认最多保留 200 条，并清理超过 7 天的数据。

## 5. 用户故事

1. 作为扩展用户，我希望看到当前页面是否兼容，以便区分 ChatGPT 本身仍在执行和扩展识别失败。
2. 作为扩展用户，我希望看到队列暂停的具体原因，以便知道应该刷新、点击继续还是等待当前任务完成。
3. 作为扩展用户，我希望复制一份诊断摘要，以便在反馈问题时不需要手工整理控制台日志。
4. 作为扩展用户，我希望下载结构化 JSON，以便开发者能够比较任务、队列、页面信号和租约状态。
5. 作为隐私敏感用户，我希望诊断默认不包含完整问题、回复和队列正文，以便安全分享。
6. 作为多标签页用户，我希望诊断能区分不同标签页和页面实例，但不暴露原始会话 ID。
7. 作为队列用户，我希望页面状态不可靠时自动执行安全暂停，以免重复发送或覆盖草稿。
8. 作为队列用户，我希望页面恢复正常后仍需明确点击继续，避免兼容性抖动触发自动发送。
9. 作为维护者，我希望任务监控和消息队列使用同一页面快照，以便一次更新即可适配新的 ChatGPT DOM。
10. 作为维护者，我希望页面状态适配层可以用固定 DOM 样本独立测试，以便在不登录 ChatGPT 时验证兼容规则。
11. 作为维护者，我希望诊断事件有稳定 Schema 和版本号，以便未来版本继续读取和比较。
12. 作为维护者，我希望新增能力不增加 Chrome 权限，以便保持当前隐私和审核边界。

## 6. 功能需求

### FR-01 统一页面状态适配层

- 提供唯一的页面状态快照入口。
- 统一活动输入框、发送按钮、停止按钮、等待确认、忙碌、错误、消息列表和复制回复按钮识别。
- 任务监控器和消息队列只能消费快照，不再直接维护重复选择器和关键词表。
- 允许任务监控器和队列在快照之上保留各自的时间窗口和业务状态机。

### FR-02 兼容性评估

- 每个快照返回 `healthy`、`degraded` 或 `blocked`。
- 返回可读原因代码和中文说明。
- `blocked` 时自动队列不得派发。
- 因兼容性阻塞而暂停的队列，页面恢复后不得自动继续，必须由用户点击“继续”。
- 任务监控器无法确认完成时保持保守状态，不得误报完成。

### FR-03 本地诊断事件

- 在本地记录重要任务、队列、租约、兼容性和通信事件。
- 事件包含时间、事件类型、结果、原因代码、脱敏标签页标识、脱敏会话标识和相关状态摘要。
- 不记录完整聊天内容、队列正文、Cookie、Token 或 DOM HTML。
- 自动限制数量和保存时间。
- 提供清除诊断记录能力。

### FR-04 诊断报告

诊断报告至少包含：

- 扩展版本、Manifest 版本和诊断 Schema 版本。
- 浏览器运行环境的可安全读取信息。
- Windows/Chrome 通知权限状态。
- 当前任务数量和脱敏任务状态摘要。
- 当前队列数量、状态、待执行数量、活动项状态和租约摘要。
- 最近页面状态快照及兼容性原因。
- 最近诊断事件。
- 数据生成时间和隐私声明。

诊断报告必须：

- 默认删除完整 URL，仅保留路由类别和不可逆短哈希。
- 默认删除提示词、回复第一行和队列正文。
- 可直接复制为 Markdown 摘要。
- 可下载为 UTF-8 JSON 文件。

### FR-05 Popup 诊断中心

- Popup 顶部显示总体健康状态。
- 显示通知权限、活动任务、队列状态和当前页面兼容性摘要。
- 提供“复制诊断信息”“下载诊断 JSON”“清除诊断记录”操作。
- 复制和下载成功后显示明确反馈。
- 没有打开 ChatGPT 页面时仍能导出扩展、任务历史和本地队列摘要。

### FR-06 安全降级

- 页面适配状态为 `blocked` 时，不得自动发送队列消息。
- 不得通过刷新页面、重新打开页面或创建新标签尝试恢复。
- 不得覆盖当前草稿。
- 已经进入发送确认阶段的消息继续按现有确认机制处理，不能因为快照模块切换而重复派发。
- 兼容性从 `blocked` 恢复后，显示恢复提示，但保持队列暂停直到用户继续。

## 7. 数据与隐私要求

- 不新增 Chrome 权限。
- 所有诊断数据只保存在 `chrome.storage.local`。
- 诊断事件最多 200 条，默认保留 7 天。
- 诊断 Schema 必须带版本号。
- 会话标识使用带扩展本地随机盐的不可逆短哈希，不输出原始会话 ID。
- 标签页 ID 可在当前诊断中使用，但不得与完整 URL 或聊天正文组合。
- 错误信息必须经过长度限制和敏感字段过滤。
- 清除诊断记录不影响任务、设置和消息队列。

## 8. 实现决策

1. 页面状态适配层是 v0.7.0 的最高测试缝隙：DOM 输入进入适配层，任务监控器和消息队列只消费结构化快照。
2. 适配层只负责事实采集和兼容性判断，不负责决定任务完成或队列项完成。
3. 任务和队列继续保留各自的时间稳定窗口、基线哈希、发送确认和租约规则。
4. 诊断事件通过统一记录器写入，业务模块只提交结构化事件，不直接操作诊断 Storage。
5. Popup 通过 Service Worker 获取汇总后的公开诊断数据，不直接遍历所有内部 Storage 键。
6. 诊断报告采用稳定 Schema，可在后续版本向后兼容读取。
7. 页面状态或诊断模块异常时，核心原则是暂停自动执行而不是尝试恢复页面。
8. 不引入新的生产依赖；继续使用原生 JavaScript 和 Chrome Extension API。

## 9. 测试决策

### 9.1 页面状态适配测试

使用可控 DOM fixture 验证：

- 普通会话、项目主页、项目正式会话和临时会话。
- 隐藏旧输入框与多个可见输入框。
- 新旧发送按钮、停止按钮和确认按钮。
- 复制回复按钮存在与缺失。
- 忙碌、错误和无核心输入框场景。
- `healthy`、`degraded`、`blocked` 分类和原因代码。

测试只断言公开快照，不断言内部选择器调用次数。

### 9.2 任务与队列集成测试

- 任务监控器使用共享快照后保持现有开始、恢复、完成、失败和页面切换行为。
- 队列使用共享快照后保持加入、自动执行、立即执行、发送确认、刷新暂停和租约互斥行为。
- `blocked` 状态不会发送消息。
- 恢复到 `healthy` 后不会自动解除兼容性暂停。

### 9.3 诊断与 Popup 测试

- 事件数量、过期清理和 Schema 迁移。
- 报告不包含完整提示词、回复、队列正文、Cookie、Token 和原始会话 ID。
- Markdown 复制与 JSON 下载数据一致。
- 清除诊断记录不删除设置、任务和队列。
- Popup 在无 ChatGPT 页面、正常页面和阻塞页面下均可显示。

### 9.4 浏览器回归

- 无登录 Playwright 扩展加载和 Popup 操作。
- 模拟正常与不兼容 DOM 的安全暂停。
- 已登录 Profile 2 的普通会话和项目会话人工验收。
- Windows 通知测试保持通过。

## 10. 验收标准

v0.7.0 完成需同时满足：

1. 任务监控器与消息队列不再重复维护核心页面状态选择器和关键词。
2. Popup 可显示页面兼容性健康状态及原因。
3. 页面被判定为 `blocked` 时，自动队列不会发送消息。
4. 用户可复制脱敏 Markdown 诊断摘要并下载 JSON。
5. 诊断报告不包含完整问题、回复、队列正文、Cookie、Token 和原始会话 ID。
6. 所有现有单元测试继续通过，并新增页面快照、诊断、Popup 与安全降级测试。
7. 无登录 Playwright 冒烟通过；Profile 2 完成普通会话和项目会话关键验收。
8. Manifest 不增加权限。
9. README、CHANGELOG、PRIVACY 和 Release 说明与 v0.7.0 行为一致。
10. GitHub Release 包含可加载 ZIP 和 SHA256 校验文件。
