# gpt-notice v0.7.0 需求文档：稳定队列界面、统一页面适配与本地诊断

> 设计日期：2026-07-29
> 基线版本：v0.6.12
> 目标版本：v0.7.0
> 拷问结论：`docs/v0.7.0-grilling-decisions.md`

## 1. 背景

v0.6.12 已具备当前页面任务监控、Windows 通知、按标签页隔离的消息队列、同会话执行租约、刷新安全暂停和项目页面输入框适配。

当前主要问题是：

1. 任务监控器和消息队列分别维护 ChatGPT DOM 判断，容易规则漂移。
2. ChatGPT 流式输出会持续修改 DOM，现有 MutationObserver 会频繁安排插件 UI 渲染，可能造成按钮闪烁、列表重建和点击不稳定。
3. “加入队列”按钮会因当前任务状态或输入内容被禁用，用户无法始终通过同一入口保存后续消息并获得明确反馈。
4. 队列上下排序增加 UI、状态和测试分支，但核心使用方式仍是按加入顺序执行。
5. Popup 无法解释队列为何暂停、页面为何不兼容，也无法导出默认脱敏的诊断信息。
6. 当前运行资产约 189 KB，其中队列主脚本约 69 KB；真正需要收缩的是重复职责和单文件复杂度，而不是为少量字节引入构建工具。

## 2. 目标

v0.7.0 应同时实现：

- 建立任务监控器和消息队列共同使用的页面事实适配层。
- 将页面支持范围、兼容性等级和安全能力明确分离。
- 让“加入队列”在 ChatGPT 工作页面中始终可见、可点击并返回明确结果。
- 允许空闲页面保存队列，但默认暂停，只有用户明确操作后才开始执行。
- 使插件 UI 与 ChatGPT 回复流式 DOM 更新解耦，回复输出时不重建按钮和队列列表。
- 将队列固定为按加入顺序执行，移除上下调整位置。
- 在 Popup 中提供完全本地、默认无正文的诊断中心。
- 删除重复 DOM 判断、全局查询补丁和无入口排序逻辑，控制单文件复杂度和运行资产增长。

## 3. 非目标

v0.7.0 不包含：

- 关闭 ChatGPT 标签页后继续监控。
- 后台标签、隐藏窗口、折叠标签组或自动恢复已关闭页面。
- ChatGPT 私有 API、Cookie 读取、诊断上传或云同步。
- 自动刷新页面、绕过真人验证或强制绕过兼容性阻塞。
- 附件、图片、模型、工具和模式配置队列。
- 队列拖拽排序、上移或下移。
- 为压缩几十 KB 引入打包器、压缩器或生产依赖。
- Chrome Web Store 正式发布。

## 4. 核心模型

### 4.1 页面支持状态

- `initializing`：页面仍在加载或 SPA 重挂载宽限期内，禁止派发但不正式暂停。
- `supported`：属于扩展支持的工作页面，需要继续评估兼容性。
- `unsupported`：ChatGPT 登录页、设置页、共享只读页或未知非工作路由，不属于故障。

页面初始化宽限期默认不超过 3 秒。

### 4.2 工作页面类型

- `draft`：普通首页或项目主页，尚未绑定正式会话 ID。
- `provisional_conversation`：已有内容但使用 `WEB:` 临时标识。
- `conversation`：稳定 `/c/<conversation-id>` 会话。

### 4.3 页面状态快照

页面状态快照只描述某一时刻的可观测事实，包括：

- 活动输入框是否存在、可见、可用、为空。
- 发送、停止、等待确认等控件是否存在且可用。
- 用户与助手消息数量。
- 回复是否变化、复制回复按钮数量。
- 忙碌和明确错误信号。
- 工作页面类型和页面实例短标识。

内部快照可以持有 DOM 节点；公开快照只能包含可序列化数据。公开快照和诊断报告不得包含完整正文、原始 URL、原始会话 ID、真实 Tab ID或稳定内容哈希。

### 4.4 页面适配评估

支持页面使用三种兼容性等级：

- `healthy`：核心信号完整且一致。
- `degraded`：部分信号缺失，但存在安全替代信号。
- `blocked`：核心事实缺失或冲突，无法安全完成某些操作。

评估必须同时输出：

- `canTrackTask`
- `canDetectCompletion`
- `canAdmitQueue`
- `canDispatchQueue`
- `canWriteComposer`
- `canClickSend`
- 稳定的原因代码和中文说明

健康等级不直接代替能力判断。

### 4.5 兼容性暂停

短暂 DOM 抖动先经过 2～3 秒稳定窗口。只有持续阻塞或强冲突信号才进入正式兼容性暂停。

正式暂停后：

- 不自动派发。
- 不重新申请会话执行租约。
- 页面恢复时显示提示，但必须由用户点击继续。
- 不提供强制绕过安全判断的自动执行。
- 已经确认发送的活动项继续监控，不得重复派发。

## 5. 用户故事

1. 作为用户，我希望加入队列按钮一直可见可点，以便无论当前任务状态如何都能通过同一入口得到明确结果。
2. 作为用户，我希望空闲时也能保存后续消息，以便先整理队列，再决定何时开始。
3. 作为用户，我希望回复流式输出时插件按钮和队列列表保持稳定，以免闪烁、误点或焦点丢失。
4. 作为用户，我希望队列按加入顺序执行，以便行为简单且可预测。
5. 作为用户，我希望页面不兼容时队列安全暂停，以免重复发送或覆盖草稿。
6. 作为用户，我希望知道暂停或无法执行的具体原因。
7. 作为用户，我希望复制或下载默认脱敏的诊断报告。
8. 作为多标签用户，我希望每个页面实例独立评估兼容性，不让一个异常标签影响另一个正常标签。
9. 作为维护者，我希望任务和队列只消费统一页面快照，以便一次适配 ChatGPT DOM 变化。
10. 作为维护者，我希望插件保持原生、无生产依赖，并通过职责拆分降低单文件复杂度。

## 6. 功能需求

### FR-01 统一页面事实适配层

- 提供唯一的页面快照和页面适配评估入口。
- 统一输入框、发送、停止、确认、忙碌、错误、消息和复制按钮识别。
- 任务和队列不得继续维护重复选择器或错误关键词表。
- 迁移完成后移除对 `document.querySelector` 的全局覆盖。
- 页面事实和业务状态机分离；适配层不得直接判断任务或队列项完成。

### FR-02 支持状态、兼容性和能力

- 区分 `initializing`、`supported`、`unsupported`。
- 支持页面返回 `healthy`、`degraded` 或 `blocked`。
- `degraded` 只有在存在安全替代信号时成立。
- `blocked` 不结束任务；无法确认完成时保持保守运行状态。
- 阻塞属于页面实例，不得扩散到同会话其他标签。

### FR-03 加入队列按钮始终可用

- ChatGPT 工作页面中的加入队列入口始终可见、可点击，不因输入为空、没有活动任务、队列暂停或兼容性状态而设置业务性 `disabled`。
- 内部动作锁防止重复点击，但保持同一按钮 DOM 节点并显示处理反馈。
- 输入为空时提示，不创建空项。
- 没有活动任务时允许入队，新队列默认暂停，不自动发送。
- 用户可通过“立即执行”或“开始/继续”明确启动。
- 兼容性阻塞时，只有 `canWriteComposer` 为真且输入框目标唯一时才允许保存；保存后继续暂停。
- 无法安全清空输入框时不得创建队列项，也不得改变用户草稿。

### FR-04 稳定插件 UI

- 每个页面实例只挂载一次插件根节点和一次事件委托。
- SPA 跳转不得重建插件根节点；完整刷新自然创建新实例。
- MutationObserver 只安排页面检查，不直接安排 UI 重绘。
- UI 只在派生 UI 模型变化、Storage 变化、用户操作或明确通知变化时更新。
- 回复 token 和助手正文字符变化不得重建插件按钮或整个队列列表。
- 队列列表按队列项 ID 增量更新；禁止在普通检查循环中整体替换 `innerHTML`。
- 暂不引入 Shadow DOM。

### FR-05 FIFO 队列

- 删除上移、下移按钮和排序能力。
- 普通自动执行严格按加入顺序处理。
- 编辑和失败重试保持原有位置。
- “立即执行”保留为用户明确选择的例外；执行后其余队列项相对顺序不变。
- 删除排序事件、纯函数、样式和测试中的死代码。

### FR-06 安全派发

- 启动自动派发前必须满足 `canDispatchQueue` 和 `canWriteComposer`；消息写入输入框后，再等待 `canClickSend` 成立才点击发送。空输入框尚未渲染发送按钮不应阻止队列开始写入。
- 正式兼容性暂停恢复后不得自动继续。
- 输入框有草稿时继续使用明确覆盖确认。
- 已进入发送确认阶段的消息不得因快照切换、页面抖动或租约变化重复派发。
- 持有租约的页面正式阻塞时释放租约，但恢复后需人工继续才能重新竞争。

### FR-07 本地诊断事件

- 事件由 Service Worker 统一规范化、脱敏、聚合、裁剪和写入。
- 只记录兼容性、能力、任务、队列、租约、发送和通信的关键变化。
- 不记录每次轮询、每次成功心跳、每次租约续期或每个回复 token。
- 相同页面实例、事件类型和原因代码在短窗口内聚合。
- 最多 200 条，最多保留 7 天，并在写入或生成报告时惰性清理。
- 诊断写入失败不得影响任务和队列。

### FR-08 脱敏诊断报告

报告至少包含：

- 扩展、Manifest、页面快照、事件和报告 Schema 版本。
- 浏览器主版本、平台类型和通知权限。
- 任务、队列、页面适配和租约的脱敏摘要。
- 最近诊断事件和生成时间。

报告必须：

- 使用本地随机盐和 SHA-256 生成不可逆短会话标识。
- 使用本次报告内的 `tab-1`、`tab-2` 等别名。
- 默认移除标题、提示词、回复第一行、队列正文、完整 URL、原始会话 ID、真实 Tab ID、设备名、用户名、本地路径、Cookie 和 Token。
- 由允许列表构造，不直接序列化内部对象或异常。
- 使用同一个公开模型生成 Markdown 摘要和 UTF-8 JSON。

### FR-09 Popup 诊断中心

- 分别展示页面兼容性、通知权限、活动任务和消息队列，不用一个模糊状态掩盖各维度。
- 总体主状态优先显示页面阻塞、通知拒绝、队列暂停/失败、页面降级和正常。
- `unsupported` 当前页面不覆盖其他标签中的活动任务状态。
- 提供复制诊断、下载 JSON、清除诊断和重新检测。
- 剪贴板写入失败时显示可手动复制文本。
- 清除诊断需确认，且不影响任务、队列、设置和诊断盐。
- 没有当前工作页面时仍可导出基础诊断。

### FR-10 内部精简与体积控制

- 保持原生 JavaScript、零生产依赖和可直接调试源码。
- 不引入打包器或压缩器。
- 将页面适配、队列 UI、队列 Storage/租约、队列运行编排按职责分离。
- 将长期运行脚本名从带历史版本号的名称迁移为稳定名称；Storage Schema 独立版本化。
- 只保留一个页面检查调度器和一个 UI 更新调度器。
- Release 继续排除测试、文档、脚本和开发依赖。
- 运行 JS、HTML、CSS 和 Manifest 未压缩总量目标不超过 175 KB；任一运行 JavaScript 文件目标不超过 50 KB。超过目标需在发布说明中解释并确认无重复逻辑或误打包文件。

## 7. 数据与 Storage

建议独立键：

- `diagnosticEventsV1`
- `diagnosticMetaV1`
- `diagnosticSaltV1`
- `latestPageDiagnosticsV1`

规则：

- 每个页面实例只保留最近一份公开快照，超过 24 小时忽略。
- 页面快照、诊断事件和报告分别版本化。
- 旧或损坏诊断数据优先丢弃重建，不阻止扩展启动。
- 清除诊断不删除随机盐。
- Storage 配额不足时优先保护任务、队列和设置。

## 8. 测试决策

### 8.1 页面适配

- 使用最小语义 DOM fixture 覆盖草稿页、临时会话、正式会话、项目页、非工作页和未知路由。
- 覆盖隐藏旧输入框、多个可见输入框、缺失发送按钮、忙碌、错误、初始化和冲突信号。
- 主要断言公开快照、兼容性和能力，不断言内部选择器调用次数。

### 8.2 队列和稳定 UI

- 按钮在空输入、空闲、运行、暂停、阻塞状态下均可点击并产生明确反馈。
- 空闲入队后默认暂停，不自动发送。
- 流式模拟大量 `characterData` 变化时，插件根节点和按钮节点引用保持不变。
- 回复 token 变化不触发队列列表整体替换。
- FIFO、重试保序和立即执行后的剩余顺序均有测试。
- 不再存在上移、下移入口或排序能力。

### 8.3 诊断与隐私

- 测试事件聚合、数量裁剪、过期清理和损坏数据恢复。
- 使用 URL、邮箱、Token、JWT、Cookie、会话 ID 和本地路径恶意样本，断言 Markdown 和 JSON 均不泄露。
- Markdown 与 JSON 来自同一公开报告模型。

### 8.4 发布门禁

自动门禁：

- JavaScript 语法检查。
- 单元与静态测试。
- 无登录 Playwright。
- Release 打包文件检查和运行资产体积统计。

人工门禁：

- 当前已登录 Chrome 的普通会话和项目会话。
- 空闲入队、运行中入队、兼容性暂停和人工继续。
- 流式输出时插件按钮不闪烁、不重建。
- Windows 通知。
- Markdown 和 JSON 脱敏人工检查。

## 9. 验收标准

v0.7.0 完成需同时满足：

1. 任务和队列不再重复维护核心 DOM 选择器和错误关键词。
2. 页面支持状态、兼容性等级和能力标志可以独立测试。
3. 加入队列按钮在工作页面中始终可点击，并在所有状态下返回明确结果。
4. 空闲入队默认暂停，不发生隐式自动发送。
5. ChatGPT 流式输出不会重建插件根节点、按钮或整个队列列表。
6. 队列固定 FIFO，代码和界面中不存在上下排序能力。
7. 正式兼容性暂停恢复后必须人工继续。
8. Popup 可展示分维度状态，并复制 Markdown、下载 JSON、清除诊断。
9. 诊断不包含聊天正文、完整 URL、原始会话 ID、真实 Tab ID、Cookie、Token 或本地身份信息。
10. 诊断失败不影响任务监控和消息队列。
11. 不新增 Chrome 权限、生产依赖或后台恢复行为。
12. 自动门禁全部通过；人工门禁未完成时必须明确标记未验证。
13. README、CHANGELOG、PRIVACY 和 Release 说明与实际行为一致。
