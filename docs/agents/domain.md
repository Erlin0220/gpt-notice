# Domain Docs

本仓库采用单一上下文领域文档结构。工程技能探索代码、生成规格、拆分任务或设计模块前，应按本文件读取领域术语与架构决策。

## 探索前读取

- 根目录 `CONTEXT.md`：项目领域术语、状态名称和统一语言。
- `docs/adr/`：影响当前工作区域的架构决策记录。

文件尚不存在时直接继续，不需要把缺失本身视为问题，也不要预先创建空文档。`/domain-modeling` 应在真正形成术语或决策时再创建和更新它们。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/
│   ├── agents/
│   │   ├── domain.md
│   │   ├── issue-tracker.md
│   │   └── triage-labels.md
│   └── adr/
│       ├── 0001-*.md
│       └── 0002-*.md
└── 扩展源码与测试
```

## 使用统一语言

Issue 标题、规格、开发计划、测试名称和代码设计必须优先使用 `CONTEXT.md` 中定义的术语。不要为已有概念随意引入同义词。

遇到尚未定义但会反复出现的重要概念时，应记录为 `/domain-modeling` 的候选项，而不是在不同文档中各自命名。

## 处理 ADR 冲突

新需求或实现方案与现有 ADR 冲突时，必须明确指出冲突及理由，不得静默覆盖原决策。例如：

> 与 ADR-0003“关闭页面即停止监控”冲突；只有在重新评估产品边界后才能变更。
