# gpt-notice v0.7.0 开发计划

> 对应需求：`docs/v0.7.0-diagnostics-requirements.md`
> 拷问结论：`docs/v0.7.0-grilling-decisions.md`
> 基线版本：v0.6.12
> 计划粒度：中等，按依赖顺序执行

## 1. 实施原则

1. 先建立统一页面事实和能力契约，再迁移任务、队列和诊断。
2. 页面观察与插件 UI 更新分离；回复 token 变化不能直接触发插件重绘。
3. “加入队列始终可用”表示入口始终可点击并明确反馈，不表示绕过安全校验。
4. 空闲入队默认暂停；正式兼容性暂停恢复后必须人工继续。
5. 队列按加入顺序执行，移除上下调整；“立即执行”是用户明确选择的唯一顺序例外。
6. 通过删除重复逻辑、拆分职责和限制运行资产控制复杂度，不引入构建器或生产依赖。
7. 每个任务形成可独立验证的结果；最终发布前再执行全量浏览器和 Release 验证。

## 3. 开发任务

### V070-01 — 建立页面事实、适配评估与能力契约

**Blocked by：** 无。

**交付结果：**

一个公开入口能够区分页面支持状态、工作页面类型、页面事实、兼容性等级和安全能力，为任务、队列和诊断提供唯一事实来源。

**实现范围：**

- 定义页面快照、适配评估和独立 Schema 版本。
- 统一活动输入框、发送、停止、等待确认、忙碌、错误、消息和复制按钮识别。
- 区分 `initializing`、`supported`、`unsupported`。
- 区分草稿页面、临时会话和正式会话。
- 输出 `healthy`、`degraded`、`blocked`、原因代码和六类能力标志。
- 内部快照与公开快照分离。
- 保留现有任务和队列运行入口，为分步迁移提供兼容期。

**验收标准：**

- [ ] 普通首页、项目主页、临时会话、正式会话和非工作页面均有 fixture。
- [ ] 初始化宽限、隐藏旧输入框、多个输入框和核心信号冲突均有测试。
- [ ] 公开快照无正文、完整 URL、原始会话 ID、真实 Tab ID和稳定内容哈希。
- [ ] 健康等级和能力可以独立组合。
- [ ] 现有测试保持通过。

**最小验证：**

- 页面适配单元测试。
- 活动输入框回归。
- Manifest 加载顺序静态检查。

### V070-02 — 稳定队列 UI、始终可用入队与 FIFO

**Blocked by：** V070-01。

**交付结果：**

回复流式输出时插件按钮和队列列表保持稳定；加入队列入口始终可点击；空闲页面可保存队列；队列顺序固定为 FIFO。

**实现范围：**

- 每个页面实例只创建一个插件根节点和一个事件委托。
- 页面 MutationObserver 只安排页面检查，不直接安排 UI 重绘。
- 建立派生 UI 模型签名，只在真实 UI 状态变化时更新。
- 队列列表按队列项 ID 增量更新，不在检查循环中整体替换 HTML。
- 入队按钮不因输入为空、没有活动任务、暂停或阻塞而设置业务性 `disabled`。
- 使用内部幂等锁避免重复点击，保持按钮节点稳定。
- 空输入点击显示提示。
- 空闲入队成功后默认暂停；提供明确“开始/继续”和“立即执行”。
- 页面阻塞时仅在活动输入框唯一且可安全写入时保存，并保持暂停。
- 删除上移、下移按钮、排序事件和排序纯函数。
- 保持立即执行；执行后其余项目相对顺序不变。

**验收标准：**

- [ ] 流式模拟大量 DOM 字符变化时根节点和按钮节点引用不变。
- [ ] 回复 token 变化不重建整个队列列表。
- [ ] 按钮在空输入、空闲、运行、暂停和阻塞状态都可点击并明确反馈。
- [ ] 空闲入队不会自动发送。
- [ ] FIFO、重试保序和立即执行后剩余顺序通过测试。
- [ ] 源码和静态测试中不存在上移、下移和 `moveItem`。

**最小验证：**

- 队列 UI DOM 稳定性测试。
- 入队边界测试。
- FIFO 与立即执行测试。

### V070-03 — 让任务监控器消费统一页面事实

**Blocked by：** V070-01。

**交付结果：**

任务开始、恢复、等待操作、失败、完成和页面切换行为保持稳定，但所有页面事实来自统一适配层。

**实现范围：**

- 替换任务监控器中的重复 DOM 选择器和关键词判断。
- 保留发送确认、基线哈希、稳定时间、恢复宽限和 URL 提升状态机。
- 页面 `blocked` 时任务保持运行并继续观察，不误报完成。
- 将支持状态、兼容性和能力摘要加入探针与心跳公开数据。
- 删除任务模块迁移后的重复 helper。

**验收标准：**

- [ ] 用户消息确认后才创建任务。
- [ ] 草稿、`WEB:` 和正式会话提升行为不变。
- [ ] 复制按钮和文本稳定兜底行为不变。
- [ ] 刷新恢复和跨会话停止行为不变。
- [ ] `blocked` 不导致任务完成、失败或取消。
- [ ] 任务模块不再维护核心页面选择器和错误关键词表。

**最小验证：**

- 任务生命周期测试。
- URL 提升与页面切换测试。
- 刷新恢复和完成判断测试。

### V070-04 — 迁移队列运行并实现兼容性暂停

**Blocked by：** V070-01、V070-02。

**交付结果：**

消息队列继续支持自动续发、立即执行、草稿保护、发送确认、刷新暂停和多标签租约；页面能力不足时安全暂停。

**实现范围：**

- 队列运行只消费统一页面快照和能力标志。
- 保留稳定窗口、发送确认、活动项状态和会话执行租约。
- `canDispatchQueue`、`canWriteComposer`、`canClickSend` 同时成立才自动派发。
- 弱阻塞经过稳定窗口，强冲突立即正式暂停。
- 正式暂停时释放租约；恢复后必须人工继续才能重新竞争。
- 已确认发送的活动项只继续监控，禁止重复派发。
- 页面阻塞属于页面实例，不暂停其他正常标签的独立队列。
- 删除队列运行模块迁移后的重复 DOM helper。

**验收标准：**

- [ ] 健康页面下现有队列行为不回退。
- [ ] 阻塞页面不会点击发送。
- [ ] 草稿不会被无提示覆盖。
- [ ] 恢复后不会自动继续。
- [ ] 同会话同一时刻仍只有一个租约所有者。
- [ ] 刷新仍暂停未完成队列。
- [ ] 已确认发送的消息不会重复派发。

**最小验证：**

- 队列快照集成测试。
- 发送确认、失败恢复和刷新暂停测试。
- 多标签租约与页面实例 fencing 测试。

### V070-05 — 增加本地诊断事件与公开报告

**Blocked by：** V070-01。

**交付结果：**

Service Worker 能记录有限、聚合、脱敏的关键事件，并生成统一公开诊断模型、Markdown 摘要和 JSON 报告。

**实现范围：**

- 分别定义页面快照、诊断事件和诊断报告 Schema 版本。
- 使用独立 Storage 键保存事件、Meta、盐和最近页面公开快照。
- 页面只发送结构化事件，Service Worker 串行规范化和写入。
- 记录兼容性、能力、任务、队列、租约、发送和通信关键变化。
- 聚合短窗口内的重复事件。
- 同时限制最多 200 条和最多 7 天。
- 使用本地随机盐和 SHA-256 生成短会话标识。
- 使用允许列表生成公开报告；不序列化内部任务、队列或异常对象。
- 诊断写入失败不得影响核心业务。

**验收标准：**

- [ ] 重复事件聚合，事件数量和期限正确裁剪。
- [ ] 报告包含版本、环境、权限、任务、队列、页面和事件摘要。
- [ ] 恶意正文中的 URL、邮箱、JWT、Token、Cookie、路径和会话 ID 不出现在 Markdown 或 JSON。
- [ ] 清除诊断不影响任务、队列、设置和随机盐。
- [ ] 旧或损坏诊断数据可忽略重建。
- [ ] Storage 失败不阻塞任务和队列。

**最小验证：**

- 事件规范化、聚合、裁剪和过期测试。
- 允许列表和敏感字段测试。
- Markdown/JSON 同源测试。
- Storage 损坏与配额失败测试。

### V070-06 — 在 Popup 中提供分维度诊断中心

**Blocked by：** V070-03、V070-04、V070-05。

**交付结果：**

用户能分别看到页面兼容性、通知权限、活动任务和消息队列，并复制、下载、清除和重新检测诊断。

**实现范围：**

- 顶部显示主状态，但保留四个独立维度。
- 通过 Service Worker 探测当前活动 ChatGPT 页面公开快照。
- 区分无工作页面、页面脚本无响应和真正兼容性阻塞。
- 提供复制 Markdown、下载 UTF-8 JSON、清除诊断和重新检测。
- 剪贴板失败时展示可手动复制文本。
- Popup 不直接读取内部队列正文 Storage。
- 诊断区域异常时保留原设置、最近任务和停止监控能力。

**验收标准：**

- [ ] 正常、降级、阻塞、初始化、非工作页面和脚本无响应均有明确中文展示。
- [ ] 用户能看到自动执行被阻止或暂停的具体原因。
- [ ] JSON 文件名包含版本和时间。
- [ ] 清除诊断前确认且不误删业务数据。
- [ ] 没有工作页面时仍可导出基础诊断。
- [ ] Popup 原有能力不回退。

**最小验证：**

- Popup DOM 和消息交互测试。
- 六类页面状态渲染测试。
- 复制、手动复制、下载、清除和重新检测测试。

## 6. 风险与回滚

### 风险 1：空闲入队被误解为立即发送

- 空闲入队必须默认暂停。
- UI 明确提示“已保存，点击开始/立即执行”。
- 测试禁止入队动作隐式点击发送。

### 风险 2：UI 优化影响页面状态检查

- 页面检查和 UI 更新使用独立调度器。
- UI 不渲染不代表停止检查任务完成。
- 节点稳定性和完成检测分别测试。

### 风险 3：统一适配改变现有完成判断

- 适配层只提供事实和能力。
- 任务和队列分开迁移并可单独回滚。
- 迁移前后使用同一场景回归。

### 风险 4：职责拆分增加文件但没有减少复杂度

- 以重复逻辑、单文件大小和公开接口数量为审查标准，不以文件数量为目标。
- 不允许多个模块重新复制选择器和关键词。

### 风险 5：诊断泄露内容或影响业务 Storage

- 报告使用允许列表和恶意样本测试。
- 诊断使用独立键，写入失败可降级。
- 不通过清除业务数据解决诊断问题。

### 回滚原则

- 任一迁移任务可独立回滚，不重写用户任务和队列 Storage。
- 诊断中心可以独立关闭，不影响原设置和任务列表。
- 不恢复队列上下排序作为回滚手段。
- 不通过重新引入后台标签、自动刷新或强制自动执行恢复连续性。
