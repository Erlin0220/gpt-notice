# gpt-notice v0.7.0 开发计划

> 对应需求：`docs/v0.7.0-diagnostics-requirements.md`
> 基线版本：v0.6.12
> 计划粒度：中等，按依赖顺序执行

## 1. 实施原则

1. 先统一页面状态事实来源，再迁移任务监控和消息队列，避免两套规则继续并行扩散。
2. 每个任务都必须形成可独立验证的纵向结果，不拆成“只写模块、不接业务”的水平任务。
3. 迁移期间保持现有行为不变；兼容性安全暂停和诊断中心在统一快照稳定后启用。
4. 不增加 Chrome 权限，不引入生产依赖，不修改“关闭页面即停止监控”的产品边界。
5. 页面状态无法安全判断时暂停自动执行，不刷新、不重开、不重复发送。
6. 每个任务完成后执行受影响测试；最终收尾时再执行全量测试、浏览器回归、打包和 Release 验证。

## 3. 开发任务

### V070-01 — 建立统一页面状态快照契约

**Blocked by：** 无，可立即开始。

**交付结果：**

建立唯一的页面状态适配入口，能够从普通会话、项目页面和临时会话 DOM 生成结构化快照，并输出兼容性健康状态。

**实现范围：**

- 定义带版本号的页面状态快照契约。
- 统一活动输入框、发送按钮、停止按钮、等待确认、忙碌、错误、用户消息、助手消息和复制回复按钮识别。
- 将现有活动输入框适配逻辑纳入统一适配层。
- 增加路由类别识别和脱敏会话标识辅助能力。
- 定义 `healthy`、`degraded`、`blocked` 原因代码。
- 保持旧任务监控器和队列暂时可运行，为后续迁移提供兼容入口。

**验收标准：**

- [ ] 一个公开入口可生成完整快照。
- [ ] 快照不包含完整提示词、回复或输入框正文。
- [ ] 普通会话、项目主页、项目会话、临时会话均有 fixture 测试。
- [ ] 隐藏旧输入框、多个输入框和缺失核心控件均有测试。
- [ ] 兼容性状态和原因代码稳定、可序列化。
- [ ] 现有测试保持通过。

**最小验证：**

- 页面状态适配层单元测试。
- 活动输入框原有回归测试。
- Manifest 内容脚本加载顺序检查。

### V070-02 — 让任务监控器消费统一快照

**Blocked by：** V070-01。

**交付结果：**

任务开始、运行、等待操作、失败、完成和页面切换继续按原有行为工作，但所有页面事实来自统一快照。

**实现范围：**

- 用共享快照替换任务监控器中的重复 DOM 选择器和关键词判断。
- 保留任务监控器自己的基线哈希、稳定时间、恢复宽限期和完成状态机。
- 将页面兼容性状态纳入任务探针和心跳摘要。
- `blocked` 时保持保守监控，不得凭缺失信号误报完成。
- 删除迁移后不再使用的重复判断代码。

**验收标准：**

- [ ] 用户消息确认后才创建任务的行为不变。
- [ ] 草稿页、临时 WEB 会话和正式会话 URL 提升行为不变。
- [ ] 复制回复按钮和文本稳定兜底完成判断不变。
- [ ] 页面刷新恢复和跨会话停止行为不变。
- [ ] `blocked` 快照不会导致误完成。
- [ ] 任务监控器不再维护核心页面选择器和错误关键词表。

**最小验证：**

- 任务生命周期测试。
- URL 提升与页面切换测试。
- 恢复和完成判断测试。

### V070-03 — 让消息队列消费统一快照并支持兼容性暂停

**Blocked by：** V070-01。

**交付结果：**

消息队列继续支持加入、编辑、立即执行、自动续发、刷新暂停和多标签互斥；页面状态为 `blocked` 时安全暂停并显示明确原因。

**实现范围：**

- 用共享快照替换队列中的重复输入框、发送、停止、确认、忙碌、错误和回复识别。
- 保留队列自己的稳定窗口、发送确认、活动项状态和执行租约。
- 新增兼容性暂停原因和用户可见提示。
- 兼容性恢复后保持暂停，必须由用户点击继续。
- 确保已进入发送确认阶段的消息不会因快照切换被重复派发。
- 删除迁移后不再使用的重复页面状态代码。

**验收标准：**

- [ ] `healthy` 页面下现有队列流程行为不变。
- [ ] `blocked` 页面下自动执行不会点击发送按钮。
- [ ] 输入框草稿不会被覆盖。
- [ ] 恢复到 `healthy` 后不会自动继续。
- [ ] 同会话多标签仍只有一个执行租约所有者。
- [ ] 页面刷新仍统一暂停未完成队列。
- [ ] 队列模块不再维护核心页面选择器和错误关键词表。

**最小验证：**

- 队列纯函数和页面快照集成测试。
- 发送确认、失败恢复和刷新暂停测试。
- 多标签租约与页面实例 fencing 测试。

### V070-04 — 增加本地诊断事件与脱敏报告

**Blocked by：** V070-01。

**交付结果：**

扩展能够记录有限数量的结构化诊断事件，并由 Service Worker 生成可复制、可下载且默认脱敏的诊断报告。

**实现范围：**

- 定义诊断 Schema 版本、事件类型和公开报告结构。
- 实现最多 200 条、最多 7 天的本地环形事件记录。
- 记录任务、队列、租约、页面兼容性和通信关键事件。
- 使用本地随机盐生成不可逆短会话哈希。
- 生成 Markdown 摘要和 JSON 报告。
- 对错误文本执行长度限制和敏感字段过滤。
- 提供读取与清除诊断记录的 Service Worker 消息接口。

**验收标准：**

- [ ] 事件超出数量或保存期限后自动清理。
- [ ] 报告包含版本、权限、任务、队列、快照和事件摘要。
- [ ] 报告不包含完整问题、回复、队列正文、Cookie、Token、原始会话 ID 和完整 URL。
- [ ] 清除诊断不影响设置、任务和队列。
- [ ] 旧或损坏诊断数据能够安全忽略或迁移。
- [ ] 无需新增 Chrome 权限。

**最小验证：**

- 事件规范化、裁剪和过期清理测试。
- 敏感字段过滤测试。
- Markdown 与 JSON 报告一致性测试。
- Storage 损坏恢复测试。

### V070-05 — 在 Popup 中提供诊断中心

**Blocked by：** V070-02、V070-03、V070-04。

**交付结果：**

用户打开扩展 Popup 即可看到总体健康状态、页面兼容性、任务和队列摘要，并可复制或下载诊断信息。

**实现范围：**

- 在 Popup 顶部增加总体健康状态卡片。
- 显示通知权限、活动任务、当前页面兼容性和队列暂停原因。
- 增加“复制诊断信息”“下载诊断 JSON”“清除诊断记录”按钮。
- 增加成功、失败和无当前 ChatGPT 页面时的状态反馈。
- 保留现有通知设置、最近任务、打开任务和停止监控能力。
- 确保 Popup 不直接读取内部队列正文 Storage。

**验收标准：**

- [ ] `healthy`、`degraded`、`blocked` 有清晰中文展示。
- [ ] 用户能看到自动执行被阻止的具体原因。
- [ ] Markdown 可复制，JSON 可下载且文件名包含时间和版本。
- [ ] 清除诊断前需要明确确认。
- [ ] 没有打开 ChatGPT 页面时仍可导出基础诊断。
- [ ] Popup 原有设置和任务操作不回退。

**最小验证：**

- Popup DOM 与消息交互测试。
- 正常、降级、阻塞和无页面状态渲染测试。
- 复制、下载和清除操作测试。

## 5. 提交建议

按任务形成独立提交，建议顺序：

1. `feat(dom): 建立统一页面状态快照与兼容性评估`
2. `refactor(task): 迁移任务监控到共享页面状态适配层`
3. `feat(queue): 支持页面兼容性阻塞与安全暂停`
4. `feat(diagnostics): 增加本地事件记录与脱敏诊断报告`
5. `feat(popup): 增加页面健康状态与诊断导出入口`
6. `release: 发布 gpt-notice v0.7.0`

每次提交前执行对应最小验证和 `git diff --check`；最终发布前执行全量验证。

## 6. 风险与回滚

### 风险 1：统一快照改变现有完成判断

- 先建立适配层并保持旧行为测试。
- 任务和队列分开迁移，禁止一次性重写两套状态机。
- 快照只提供事实，不把业务完成规则下沉。

### 风险 2：诊断记录增加 Storage 写入频率

- 只记录状态变化和关键动作，不记录每次轮询。
- 批量或节流写入事件。
- 固定数量和保存时间上限。

### 风险 3：诊断信息泄露聊天内容

- Schema 采用允许列表，不对内部对象直接序列化。
- 对所有字符串做敏感字段过滤和长度限制。
- 增加禁止出现提示词、回复、Token 和原始会话 ID 的测试。

### 风险 4：兼容性抖动频繁暂停队列

- `blocked` 需要稳定窗口或明确核心信号缺失。
- `degraded` 只提示，不直接暂停。
- 一旦因兼容性暂停，恢复后由用户明确继续。

### 回滚原则

- 任一迁移任务出现行为回退时，可单独回滚该迁移提交，保留已完成的页面状态适配层。
- 诊断中心可独立关闭，不影响原任务和队列 Storage。
- 不通过删除用户队列或任务数据完成回滚。
